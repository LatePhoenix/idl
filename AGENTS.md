# Agent instructions — iDL

iDL ("idle") is an Android-first ambient-presence app: friends pin each other's expressive avatar
on their home screen, and the avatar shows mood, availability and activity at a glance.
Read `docs/IDL_PRODUCT_SPEC.md` for the product and `docs/IDL_DECISIONS.md` for decisions that
are already made. **Do not reopen a recorded decision without asking the user.**

reviewable steps, and open a PR. Visual or widget changes need a device screenshot or a snapshot

## Commands

```bash
scripts/check.sh            # REQUIRED before every commit: unit tests + snapshot verify + lint + debug build
scripts/check.ps1           # the same checks in Windows PowerShell, when bash is not on PATH. check.sh stays canonical
scripts/check.sh --sql      # also the Supabase SQL suite + PostgREST IT (needs Docker running)
scripts/check.sh --device   # also instrumented tests (emulator; set ANDROID_SERIAL=emulator-5554)
./gradlew testDebugUnitTest --tests '*AvatarResolverTest*'   # one test class
./gradlew testDebugUnitTest -Pidl.updateGolden=true           # regenerate contract/privacy_vectors.json
./gradlew recordRoborazziDebug                            # record widget snapshot goldens into app/src/test/snapshots
./gradlew verifyRoborazziDebug                            # fail when a golden differs; scripts/check.sh runs this
python tools/studio/studio.py serve                # Art Studio viewer on 127.0.0.1:8765 (operator tool, D-50)
```

Requirements: JDK 17+ and Android SDK platform 35. `local.properties` (gitignored) needs `sdk.dir`.

## Architecture (short)

- `app/src/main/java/app/idl/domain/`: **pure Kotlin, no Android imports.** Presence
  precedence, expiry, privacy filter, avatar model. All of it is unit-testable on the JVM.
  - `domain/avatar/`: avatar model v2, asset manifests, compatibility and resolution (Phase 1).
- `data/`: Room cache, repositories, `IdlBackend` (+ `FakeIdlBackend` demo,
  `supabase/SupabaseIdlBackend`).
- `avatar/`: Canvas renderer (shared by the app and widgets). `widget/`: Glance widgets.
  `ui/`: Compose screens. `work/`: WorkManager.
- `AppContainer`: manual DI (no Hilt; D-02).
- `supabase/migrations/`: the server. **RPC-only API**: RLS on, no table grants (D-21).
- `contract/privacy_vectors.json`: generated by Kotlin; the SQL must match it exactly.

## Invariants — never break these

1. **Privacy is enforced server-side.** Client code never hides a field that the server sent.
   Friend data arrives already filtered (`PresenceView`).
2. **Hidden state must never leak through visuals.** If a viewer can't see `mood`, nothing
   derived from mood may affect their render: expression, overlays, or `mood:*` overrides.
   The same holds for every category.
3. **Every status expires.** Expiry is evaluated at read/render time with an injected `IdlClock`,
   never `Instant.now()` inside domain logic.
4. **Manual status beats automated sources** for mood, availability, intent and note
   (`PresenceResolver`).
5. **Saved avatars never break.** Asset removals need a `retired` mapping; schema changes need
   a migration plus tests. No destructive Room migrations.
6. **Core emotional vocabulary is never paywalled or missing** (master plan §17.3).
7. **Availability is never color-only** (D-28).
8. **Determinism:** the same inputs give the same resolved layers and render key. No `random()`
   without an explicit seed, and no dependence on hash-map iteration order.
9. **The domain layer stays Android-free.**
10. **No Charge notifications.** Nothing notifies about Charge, earnings, or a lost tether (D-30b).
11. **Never show who has or hasn't pinned you.** No per-friend tether mark, count, or exact
    hourly rate. The Status Deck shows the balance and a qualitative earning state only (D-30a).
12. **No streaks, decay, or come-back mechanics** (D-30b).
13. **The 24 h Charge cap is a ceiling, not a penalty**, and is explained in-app (D-30b, C.5).

## Conventions

- Kotlin, official style; match the surrounding code's comment density and naming.
- Enums that cross the wire use `WireEnumSerializer` (lowercase snake case, safe fallback for
  unknown values).
- JSON goes through `IdlJson`. Timestamps are ISO-8601 UTC strings via `InstantSerializer`.
- Don't add dependencies without approval. Already approved but not yet added: Roborazzi +
  Robolectric, `androidx.compose.material3.adaptive`. OkHttp is already in.
- Tests: JUnit4 + `kotlinx-coroutines-test`. Name test methods with backticks describing
  behaviour. Every bug fix gets a regression test.
- Logging via `IdlLog` with stable event names. Never log note text, names or avatar content.

## Environment gotchas

- Windows: run `./gradlew --stop` before `clean` (file locks on `app/build`).
- Two emulators are sometimes attached; set `ANDROID_SERIAL=emulator-5554` for device tests.
- `supabase/tests/run.sh` needs Docker Desktop running; it uses ports 54330 and the `idl-test`
  compose project.

## Checkpoint report (required when handing work back for review)

Write a report at the end of each task as `docs/handoff/reports/<date>-<task>.md`. Include:

- What was implemented, mapped to the task's acceptance criteria (met / not met)
- Files created or changed
- Exact commands run and their results (test counts, lint result)
- Deviations from the spec, and why
- Known limitations and open questions
- The commits made (`git log --oneline` for the range)

Never claim something works unless it was built and tested. If a check fails, say so.
