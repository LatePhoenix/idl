## What was implemented

- **`assets/packs/core_proto/v1/manifest.json`** — placeholder pack `core_proto` v1, renderer 2, procedural assets only. Five bases share the specified anchors and face-safe zone. Twelve palettes use `AvatarPalette.body[0..11]`, accents `AvatarPalette.theme` at indexes `0,2,4,5,3,1,3,0,0,1,2,3`, and outlines from the same 35% darken as `AvatarRenderer.darken` (signed 32-bit ARGB). Expressions, semantics, conflicts, occlusion, and glyphs match §1.1. `AssetRegistry.validate()` is empty.
- **`AssetPacks`** — `SHIPPED` plus `registry(read)`. Tests read `app/src/main/assets/` from the repo root the same way `PrivacyVectorsTest` does.
- **`AvatarResolver`** — §11.2 without drawing. Slot precedence, expression parts (including bot `eyes_scan`), fallback, one-sided conflicts, requirements, occlusion, target simplification, `sceneDetail`, accessibility text, and a lowercase SHA-256 render key.
- **`CompatibilityEngine`** — `validate` / `sanitize`, plus `firstFit` used by the resolver so conflict and fallback rules are not duplicated. Features (`LayerPriority.BASE`) beat accessories (`SIGNATURE`).
- **`LegacyAvatarMigration`** — v1 `AvatarConfig` to a sanitized v2 configuration, and `PresenceView` / `ResolvedPresence` to `VisiblePresence`. Expression is copied only when mood is non-null.

Hidden mood, activity, intent, and availability are not consulted: overrides and pack semantics are read only for `VisiblePresence.semanticKeys()`.

## Deviations

- **`migrate(v1, registry)`** takes an `AssetRegistry`. The spec signature has no registry, but sanitize has to see pack conflicts and palette colors, and this layer cannot open APK assets (`AssetPacks.registry` is the Phase 2 adapter).
- **`sanitize` idempotence** is on the configuration. `sanitize(sanitize(x).first).first == sanitize(x).first`, and a clean configuration returns an empty issue list, so the pairs match on a second pass. The issue list describes the input, so a dirty configuration's pair is not equal to the second call.
- **Unknown family ids** (base, palette, scene, frame, eye family, mouth family): the first non-null unknown id is replaced by the pack default and that value wins the slot. Other unknown ids are dropped with `UNKNOWN_ASSET` and the next source is tried, so an unknown presence prop still allows `defaultPropAssetId`. An unknown presence scene becomes `defaults.scene` even when a saved scene is set.
- **Default prop priority** is `SIGNATURE` (saved identity). The spec's prop column says "ACTIVITY / CONTEXT as above" and does not name a signature source. Displacement is recorded only for signature head and body accessories.
- **Reactions vs extras.** Both use `LayerPriority.DECORATION`, but compact/standard "drop DECORATION" drops expression extras only. Reactions are capped on their own (0 / 1 / 1 / 3). Dropping every `DECORATION` layer would make "keep at most 1 reaction" impossible.
- **`sceneDetail`.** `NONE` forces the scene asset to `defaults.scene` and `sceneDetail = false`. `LOW_DETAIL` is true at `sizePx >= 256`. `FULL` is true at `sizePx >= 96`.
- **Accessory vs accessory conflicts** use the same `(priority, z, id)` order as the resolver. At the same priority, lower z is kept. Migrating glasses plus a VR headset therefore keeps the glasses and drops the headset from the saved configuration. A live `activity:vr` still wins at resolve time (`ACTIVITY` beats `SIGNATURE`) and the glasses come back when the activity ends.
- **`themeColor` is dropped.** The palette accent replaces it. Noted on `LegacyAvatarMigration`.

## Limitations and open questions

- An explicit v1 clear (composed accessory `NONE` while the resting avatar has one) cannot be represented. `VisiblePresence` null means unset, so the signature accessory returns. Migration only copies a prop, scene, head, or body accessory when the composed value differs and is not `NONE`.
- Should an unknown scene id fall through to the saved scene instead of the pack default? It currently follows the step-1 reading (replace with the default).
- Phase 2 still has to load `AssetPacks.SHIPPED` through `AssetManager` and paint `ResolvedAvatar`. This phase does not change the renderer, Room, or the server.
- The accessibility sentence is base label, expression label, availability label, and activity label. Example locked by test: `Critter avatar, sleepy, text only, in VR`.
